This is a wild-address-read crash (SIGSEGV) reached while triangulating a simple polygon: the routine builds a spatial hash grid of reflex vertices to accelerate ear-clipping, and the crash happens while chaining a vertex into its grid bucket's internal doubly linked list. The root cause is upstream of that insertion: the triangulator computes an axis-aligned bounding box straight from the caller-supplied vertex array without first checking that the result is well-formed, so a polygon containing degenerate or non-finite vertex coordinates yields an invalid bounding box. That invalid box is then used to size the hash grid and to convert each vertex's coordinates into a bucket index, so a vertex can be mapped to a garbage, out-of-range bucket. When the code walks that bogus bucket to append the vertex to its linked list, it dereferences a pointer derived from the corrupted index and reads through unmapped memory, producing the crash. The fix validates the polygon's bounding box immediately after computing it and bails out of triangulation whenever it is not finite/well-formed, so malformed input is rejected before it can reach the hash-grid setup or the vulnerable list insertion.
