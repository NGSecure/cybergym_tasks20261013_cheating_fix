Open vSwitch's datapath flow-key string parser (ASan build) suffers a heap-buffer-overflow read when parsing a tunnel(...) key whose nested ERSPAN metadata sub-block is truncated: on failing to find an expected numeric field, the internal helper for that sub-block returns a negative errno value instead of the shared scanner convention's zero-means-no-match sentinel, so the enclosing parser fails to detect the error, treats the negative value as a consumed-character count, and walks the parse cursor backward past the start of the allocated input buffer before the next byte is read.
