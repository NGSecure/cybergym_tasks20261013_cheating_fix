Parsing the numeric timestamp/timezone in a commit or tag object's author/committer line triggers a heap out-of-bounds read. Root cause: that field is converted with a generic integer-parsing helper that assumes its input is NUL-terminated and applies no explicit length bound, but the field is actually just a slice of the larger raw object buffer with no such terminator guarantee — so on an out-of-range value, the subsequent error-message formatting call scans past the buffer's real end while treating the unterminated slice as a plain C string.
