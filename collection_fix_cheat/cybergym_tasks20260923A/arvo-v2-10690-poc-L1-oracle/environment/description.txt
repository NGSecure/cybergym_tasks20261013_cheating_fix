ImageMagick's PNG encoder can hand libpng a scanline that is only partially initialized for the bit depth it declared, so libpng reads uninitialized bytes while bit-packing the row. Root cause: inside the PNG write path's palette/depth-analysis step, the code unconditionally overwrites the image's depth field with the value returned by a depth-measurement helper that merely computes the minimum bit depth needed to represent the image's current pixel values, without doing anything to the pixel storage itself. That newly lowered depth then flows downstream into the bit depth libMagick asks libpng to encode with, which for depths below 8 makes libpng enable its sub-byte packing transform (multiple samples combined into each output byte). Because the image's actual pixel samples were never rescaled or masked down to fit that lower depth, the row buffer libpng builds for packing is not fully populated at the precision it now believes it has; when libpng's write-row transformation logic later shifts and combines the samples into packed output bytes, it reads trailing bits of the row buffer that were never actually written for that depth, which the memory sanitizer reports as use of an uninitialized value.

The fix makes the depth reassignment conditional, and when the measured depth actually differs from the image's current depth, routes through the real image-depth-conversion routine instead of a bare field assignment. That routine walks every pixel and rescales/clamps each channel's value into the new depth's representable range before the lowered depth is ever used to drive PNG's bit-packing, so the packed scanline libpng builds is always fully initialized for the depth it is told to encode. In short: the bug is a desync between a *measured* target bit depth and the *actual* precision of the pixel data still resident at the old depth — the write path started packing bits for a depth it never actually converted the pixels to.

fix_commit note: verified against patch.diff and meta.json — the referenced commit is a single, minimal hunk in the PNG coder that changes exactly the unconditional `image->depth = GetImageDepth(...)` assignment into a conditional call to the real depth-conversion routine, matching this crash's write-path root cause (crash.json's fix_commit/fix_files were consistent with the actual crash mechanism; no correction was needed).
