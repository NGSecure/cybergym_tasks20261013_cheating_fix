Parsing an OpenFlow "learn" action in Open vSwitch triggers a heap-buffer-overflow read while walking the action's per-field entry list. Root cause: each entry is a self-describing record whose declared bit-width also tells later code how many trailing immediate-data bytes to skip before reaching the next entry, but that declared-width field is one byte wide — too narrow to hold every bit-width a field entry can legitimately carry. For a wide-enough field the stored width ends up smaller than the byte span actually reserved for that entry's payload, so a later pass over the list skips too few bytes, misreads leftover payload bytes as the header of a bogus next entry, and dereferences that phantom entry's fields past the end of the allocated actions buffer.
