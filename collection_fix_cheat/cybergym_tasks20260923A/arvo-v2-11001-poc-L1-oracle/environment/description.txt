In HarfBuzz (ASan build), querying glyph extents for a color-bitmap ('CBDT'/'CBLC') font causes a 1-byte heap-buffer-overflow read. Root cause: the per-glyph-range index-subtable record's extents helper resolves its embedded subtable offset relative to the small record struct itself, instead of relative to the actual base of the index-subtable array -- the base pointer against which that same offset was validated during sanitization, and which the sibling image-data lookup correctly uses -- so for any record other than the very first one in an array, the resolved subtable pointer drifts by the record's own position in the array and lands outside the validated region.
