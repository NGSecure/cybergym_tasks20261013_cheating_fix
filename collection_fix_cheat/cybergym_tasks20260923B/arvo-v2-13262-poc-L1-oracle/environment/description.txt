ReadStat's SAS7BDAT reader trips a heap-buffer-overflow read (ASan) while making its second pass over a data page's subheader-pointer table. Root cause: unlike the first pass, the second pass never checks that the subheader-pointer table (header size plus pointer-count times pointer-entry size) actually fits inside the page before iterating over it, so on a malformed/truncated page the loop walks past the end of the heap-allocated page buffer and reads a trailing subheader pointer's offset/length fields out of bounds.
