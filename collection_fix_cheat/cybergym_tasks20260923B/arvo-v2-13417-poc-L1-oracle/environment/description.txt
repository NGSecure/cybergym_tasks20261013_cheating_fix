Skia's image-filter deserialization fuzz target (MSan build) exercises the path that renders an ambient drop shadow for a filled path: SkOffsetSimplePolygon() is asked to inset/outset the path's vertex ring by a signed offset distance, and it always emits both an output vertex array and a parallel same-length index array that maps each output vertex back to the vertex it came from in the original ring. When the requested offset rounds to (numerically) zero, the function takes a short-circuit branch that just copies the input vertices straight into the output vertex array, but that branch never appends anything to the parallel index array, so the index array comes out shorter than the vertex array while the caller still assumes the two stay in lockstep. The shadow ring-stitching routine that consumes this result immediately afterward walks the index array for exactly as many entries as there are output vertices, so once it runs past the entries that were actually appended it is reading heap memory that was reserved for the array but never written — MemorySanitizer flags this as a use of an uninitialized value.
