radare2 (ASan build): after shrinking the core's I/O read block size down to a single byte and then enabling the "lines.to" config option (which asks radare2 to build a byte-offset-to-line-number cache over the range from "lines.from" up to the given address), the cache-building routine allocates an array sized to the current block size and unconditionally reserves its first slot for the base address before it starts scanning for newline bytes. When the block size is only one element, that single reserved slot already consumes the entire allocation, so the very first newline the scan finds is recorded one 8-byte slot past the end of the freshly allocated cache. The capacity-growth check that would normally realloc the array only runs after each write completes rather than before it, so this first write lands as an 8-byte heap-buffer-overflow before any growth check has a chance to fire.
