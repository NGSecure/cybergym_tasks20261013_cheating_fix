When OpenThread parses a Channel Mask option carried in a received Thread CoAP energy-scan request, it copies the option onto a small stack buffer and walks its list of per-radio-page mask entries, treating an entry as present once the option's declared length covers only that entry's short leading fields, even though reading the entry also pulls a trailing multi-byte mask value that the declared length never guaranteed room for; a request whose Channel Mask option is truncated right after those leading fields still passes this check, so the parser reads the mask value from just past the end of the local stack buffer. Root cause: the per-entry presence check is sized against the entry's smaller base layout instead of the full entry (including its mask field) that the read actually consumes.
