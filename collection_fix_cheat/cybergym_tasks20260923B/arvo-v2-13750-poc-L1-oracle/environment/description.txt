Skia's image-filter deserialization fuzz target (ASan build): parsing a crafted serialized image filter that embeds a picture-recorded "batched image draw with per-image transforms" command triggers a heap-buffer-overflow read while the picture is replayed. Root cause: the replay path first reads a count directly from the input stream and allocates a transform-matrix array sized to that count, then separately deserializes a list of per-image entries whose attacker-controlled index field is used to independently recompute how many matrices the batch is supposed to contain. That recomputed count is never validated against the size of the matrix array that was actually allocated earlier, and it is then used to size a bulk copy out of that array; when the entry list is crafted so an index implies more matrices than were actually declared and allocated, the copy walks past the end of the heap buffer and reads adjacent heap memory.
