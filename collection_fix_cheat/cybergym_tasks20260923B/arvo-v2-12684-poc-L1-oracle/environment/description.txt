In OpenThread's CLI interpreter (AFL cli_uart_received fuzz target, ASan build), one CLI subcommand copies a user-supplied string into a fixed-size credential buffer embedded in an object, using the input's own length as the copy length with no check against the buffer's capacity. Root cause: that missing length check lets the out-of-bounds write corrupt the state of a later object sharing the same memory region, so when an unrelated CLI command is processed afterward, an ordinary read of the corrupted field dereferences a reference that no longer points anywhere valid, triggering a wild-address read.
