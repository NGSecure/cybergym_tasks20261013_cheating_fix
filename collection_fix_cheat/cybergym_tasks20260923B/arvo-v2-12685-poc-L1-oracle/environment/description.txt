Parsing a malicious DEX file in radare2 triggers a heap-buffer-overflow read while resolving a method's parameter-type list. Root cause: the code derives an offset into the loaded DEX buffer from attacker-controlled header fields and bounds-checks that offset as if only a single byte would be read, but then reads a 4-byte little-endian value starting at it — so an offset placed within the last few bytes of the buffer lets the read run past the buffer's end.
