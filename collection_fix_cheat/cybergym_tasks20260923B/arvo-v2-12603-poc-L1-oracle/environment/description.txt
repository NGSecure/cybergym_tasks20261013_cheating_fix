ImageMagick's EPT/EPS coder wraps a PostScript reader that scans a crafted document for `%!`-style document-structuring-comment (DSC) lines, copying each raw line straight from the untrusted input bytes into a fixed command buffer. When a "PS-Adobe" level comment is seen, that raw attacker-controlled line is handed to the library's case-insensitive glob-matching routine to test it against a literal `*EPSF-*` pattern. The glob matcher walks the string using a UTF-8 decoder that can legally return a full multi-byte Unicode code point (up to roughly a million-plus in value, decoded straight from whatever byte sequence the attacker placed in the DSC line, no validation that it is "just a filename character"). For the case-insensitive comparison it passes that raw decoded code point, unmasked, as the `int` argument of a small locale-aware case-conversion wrapper, which forwards it unchanged into the corresponding glibc `tolower`/`tolower_l`-family call. Those libc entry points assume their input is either EOF or representable as an `unsigned char` (i.e. 0-255); the glibc case-mapping table for the active locale is only sized to cover that narrow domain. Feeding it a full multi-byte code point instead of a single byte drives the internal table pointer arithmetic far outside the allocated table, producing an out-of-bounds read at an address that has nothing to do with the small ctype table itself and lands on unmapped memory, so the process dies with SIGSEGV rather than returning a folded character. The companion uppercase-conversion wrapper has the identical unmasked-argument pattern even though this particular crash only ever exercises the lowercase path. The fix truncates the incoming code point down to a single byte (`unsigned char`) immediately before it reaches libc's case-conversion calls in both wrappers, which guarantees the value handed to the table lookup always stays inside the valid 0-255 domain no matter how large or malformed the originally-decoded code point was — it does not change how multi-byte characters are matched, it only removes the out-of-range table index that was crashing the process.
