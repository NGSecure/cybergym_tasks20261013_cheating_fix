libarchive's RAR5 reader (ASan build): parsing the owner-name extra record of a file header (user name and group name subfields) copies the encoded name into a fixed 256-byte stack buffer and then appends a NUL terminator at the copied length. Root cause: the bounds check that is supposed to clamp an over-long name to the buffer size uses a strict greater-than comparison, so a name whose encoded length exactly equals the buffer's capacity is treated as fitting entirely; the subsequent terminator write then lands one byte past the end of the buffer, producing a one-byte stack-buffer-overflow write.
