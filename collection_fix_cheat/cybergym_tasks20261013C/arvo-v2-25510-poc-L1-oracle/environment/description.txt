Envoy's HTTP/2 client-side codec can invoke the response-metadata callback of an upstream stream whose response object has already been torn down, producing a heap-use-after-free read. When Envoy's HTTP/2 connection to an upstream hands a batch of bytes to nghttp2 for parsing, nghttp2 can walk multiple frames belonging to the same stream out of that single batch before control returns to the caller. If a HEADERS frame that completes the response (i.e. ends the stream) appears first in that batch, Envoy immediately finishes and tears down the corresponding response-handling object, releasing the wrapper that the stream had been using to forward decoded response events to the router. But if the very same batch also contains a trailing METADATA frame for that stream, nghttp2 keeps decoding it and, once the metadata payload is complete, invokes a previously-registered completion callback that still targets the now-freed response wrapper; that callback calls back into the wrapper to hand off the decoded metadata, dereferencing memory that was released moments earlier while handling the stream-ending HEADERS frame within the same read. The read is therefore use-after-free rather than out-of-bounds: the freed 896-byte allocation is read for a virtual-dispatch-style access, not walked past its bounds.
