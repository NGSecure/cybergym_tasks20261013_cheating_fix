In c-blosc2 (AddressSanitizer), decompressing a crafted chunk triggers a small heap-buffer-overflow read (1 byte, right at the tail of a ~40-byte allocation) while a third-party general-purpose compression library is consuming the compressed bytes of one data segment inside the block. The chunk header lets an attacker choose how many compressed bytes each segment claims to occupy, and the check meant to reject a claimed length that would run past the real end of the input is computed once, up front, from raw pointer arithmetic rather than by continuously tracking how much input actually remains. An oversized segment length slips through that stale check and is handed straight to the decompression library, which then reads slightly past the true end of the input buffer. The fix replaces the pointer-based end-of-input comparison with a running remaining-bytes counter that is decremented and re-validated before every read inside the per-segment loop.
