ImageMagick's MVG-vector-graphics ping path (ASan build): a wild out-of-bounds read crashes inside glibc's locale-aware case-folding routine while comparing glob-style tag/attribute names during MVG content interpretation. Root cause: the glob-pattern matcher decodes each side of the pattern as a UTF-8 code point and hands that raw code-point value straight to a shared case-conversion helper used throughout MagickCore for byte-oriented, locale-sensitive lowercasing. That helper only ever special-cased the end-of-file sentinel value before forwarding whatever it received to the C library's locale case-conversion call; a multi-byte UTF-8 code point (far outside the 0-255 range a single byte can hold) sails through unchecked and is used directly as a table index inside libc's locale ctype machinery, which assumes its argument is always representable as one byte (or the EOF sentinel). Because the index is now wildly out of the small ctype table's bounds, the pointer arithmetic lands far outside any mapped memory and the read segfaults. The crash surfaces several call frames below where the bad value originates: an MVG `caption:` primitive triggers image-property interpolation, which re-enters generic image reading and eventually reaches the glob matcher while resolving a bracketed/wildcard property expression.
