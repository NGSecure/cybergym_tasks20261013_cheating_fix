qpdf's PDF image-stream fuzz target (honggfuzz, ASan build): a PDF whose image XObject uses the DCTDecode filter is piped through qpdf's decode-pipeline wrapper into the bundled libjpeg-turbo library for JPEG decompression, using its plain single-row scanline path (no look-ahead/context row buffering). Just before the crash, the decoder logs a routine warning about an out-of-order progressive scan for one coefficient -- an artifact of the same crafted, malformed progressive stream, but unrelated to where the actual memory error occurs. During DC-coefficient smoothing for the following block, an unsigned boundary check meant to test whether a same-row neighbor one block-column to the right exists silently wraps around when the JPEG component being decoded is only one DCT block wide, so the check incorrectly reports a neighbor as present; the code then dereferences that phantom neighbor's coefficient data, reading 2 bytes out of a roughly 43 KB per-row buffer at an offset just beyond its end.
