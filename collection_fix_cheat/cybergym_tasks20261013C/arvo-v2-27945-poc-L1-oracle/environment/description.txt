Fluent Bit's record accessor engine (ASan build, reached through its dedicated record-accessor fuzz target) triggers a stack-buffer-overflow READ while translating a matched scalar field of a decoded log record back into text so it can be appended onto a growing output string. Immediately before the faulting access, execution has formatted that scalar into a small, fixed-size buffer allocated on the current call frame -- one of exactly two local objects living on that frame, sized to a few dozen bytes -- using a printf-style numeric-to-text conversion. The subsequent concatenation step that copies this buffer's contents onward is handed a byte count that comes from the conversion call's own report of how many characters the value's full textual form requires, rather than from how many bytes the fixed buffer can actually hold or how many were actually written into it. For most values the two numbers coincide and nothing goes wrong; for an input whose formatted textual length modestly exceeds the small buffer's capacity, the copy still walks the full reported length starting from the buffer's first byte, running a handful of bytes past its end and into whatever lies immediately after it on the stack -- an out-of-bounds READ on the copy's source side, not a write, since it is the just-formatted scratch value that gets overrun rather than the destination it is being copied into.
