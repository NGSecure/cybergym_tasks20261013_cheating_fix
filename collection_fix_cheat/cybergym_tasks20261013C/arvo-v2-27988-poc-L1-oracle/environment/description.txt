nDPI's `fuzz_process_packet` fuzz harness crashes with an ASan-reported SEGV that surfaces inside the sanitizer's own allocator bookkeeping (a wild-address read while walking chunk metadata during a heap deallocation), triggered by a single ~1.2KB crafted packet-decode-then-teardown iteration.

Root cause: when the harness finishes classifying a flow and tears the per-flow state object down, the teardown code treats any flow tagged as TLS *or* QUIC as if it must have populated a shared union of TLS/SSL-specific heap-allocated sub-fields — an ALPN string, a supported-TLS-versions list, issuer/subject DN strings, a certificate-fingerprint context, and an encrypted-SNI buffer — and releases each one unconditionally. That union storage, however, is shared with QUIC-specific protocol state: for a flow classified as QUIC, the bytes occupying those "pointer" slots are not real heap pointers at all, they're QUIC bookkeeping data reinterpreted as addresses. Passing that bogus value to the deallocation routine corrupts the allocator's internal walk (it tries to reach the chunk header of what it assumes is a live allocation and instead dereferences an unmapped/garbage address), which is why the crash backtrace bottoms out inside the sanitizer's own quarantine-flag/atomic-CAS machinery rather than in any code nDPI itself wrote — that machinery is just the first place the bogus address actually gets dereferenced.

fix_commit assessment: consistent with the crash. It edits exactly the per-flow teardown routine identified above — it adds an `is_quic` flag captured from the same TLS-or-QUIC classification check, and wraps the whole block of six SSL-sub-field releases in `!is_quic`, so a QUIC-classified flow no longer has those union-overlapping fields released at all. That is precisely the invalid-deallocation path the crash's allocator-internal stack points to. One caveat: crash.json's recorded fix-function name is not actually the function the patch changed — it's only the signature of the function that happens to sit immediately above the real edit in the unified diff's context lines, a diff-context artifact rather than a second implicated function. The genuinely modified routine is the per-flow cleanup code described above, which lines up with the crash chain.
