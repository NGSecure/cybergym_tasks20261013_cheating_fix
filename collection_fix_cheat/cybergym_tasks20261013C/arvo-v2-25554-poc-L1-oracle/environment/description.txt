Compiling an SkSL shader program whose body contains a switch statement with a compile-time-constant selector triggers a heap-use-after-free read inside the SkSL compiler's post-parse optimization stage.

Root cause: after the SkSL front end builds a function's control-flow graph, an optimization pass runs to a fixed point, walking each basic block in turn and, within each block, walking that block's list of statement/expression nodes to fold constants, drop dead code, and simplify control structures. When this walk reaches a switch statement whose condition it can prove constant, it rewrites that switch's node in place with the body of whichever case actually matches (or the default case, or a no-op if none matches) — and this in-place rewrite destroys the original switch statement object, which owns every one of its case branches, including all the branches that were not selected and everything they in turn contain. Because collapsing a switch this way can restructure the shape of the control-flow graph itself (case bodies elsewhere in the block list may no longer correspond to anything real), the pass sets a "structure changed, throw away this graph and rebuild it" flag whenever it performs such a rewrite. The intent is for that flag to immediately unwind all the way out to the top of the pass so a fresh graph gets built from the now-simplified function before any more nodes are inspected. The bug is that the flag is only honored by the innermost loop (the one walking nodes within the current block): as soon as that inner loop stops, the surrounding loop that walks the rest of the blocks in the same control-flow graph is allowed to keep going, because nothing checks the flag again until the very top of the whole pass. So the walk proceeds into later blocks that still belong to the graph built before the switch was collapsed — and one such block holds a node whose statement pointer lives inside one of the case branches that the collapse just tore down and freed. Visiting that node and dereferencing its statement pointer (to fold it into the running set of live definitions) reads through a smart pointer whose backing allocation no longer exists, which is the heap-use-after-free read observed here. The fix closes exactly this gap: it makes the same "structure changed" flag also break out of the loop over the remaining blocks, so no block from the stale graph is ever touched again once a switch has been collapsed — the graph is torn down and rebuilt before the walk resumes.
