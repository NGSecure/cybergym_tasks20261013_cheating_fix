In Skia's SkSL shader compiler (AddressSanitizer), compiling a shader function whose body declares two or more local variables in a single declaration statement, where a later variable's initializer expression reuses an earlier variable also declared in that same statement, triggers a heap-use-after-free read. Each IR node representing a use of a variable keeps a live, non-owning reference to the underlying variable object and adjusts a manual usage counter on that object when the node is constructed and again when it is destroyed; the variable object itself is owned by whichever lexical-scope symbol table first created it, and that symbol table is shared (reference-counted) across every place the same scope gets reused. The function inliner, when splicing a called function's body into the call site, can relocate a use of the not-yet-declared later variable into a sibling block that actually belongs to a separate, already-finished call and later gets discarded as dead/unneeded code during a compiler optimization pass. Discarding that block tears down its shared symbol table and, with it, deletes the variable object it owns — even though the correctly-ordered use of that same variable elsewhere in the still-live part of the program has not been destroyed yet and still holds its reference. When that surviving use node is finally torn down during program cleanup, it dereferences its now-dangling variable reference to update the usage counter, reading already-freed heap memory. The upstream fix stops the inliner from hoisting a variable's initializer expression past the point where a different, later-declared variable in the same declaration statement is used, so no reference to a variable can be constructed before that variable has actually been declared.
