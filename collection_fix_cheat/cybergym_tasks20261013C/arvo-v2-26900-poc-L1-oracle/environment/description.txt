OpenSC's Oberthur AuthentIC smart-card driver (project opensc, ASan build), exercised through the same PKCS#15 fuzz target's bind/select-file path, has to merge two path fragments whenever a directory is selected while another directory is already the cached "current" one: the bytes of the already-cached directory's path are kept in place at the front of a fixed 16-byte in-memory array, and the newly selected directory's own path bytes -- which were written into that very same array -- are shifted further into it to make room, with the shift distance equal to the cached path's own length and the number of bytes moved equal to the new path's length. Because the source and destination byte ranges for that shift both live inside the same 16-byte array, and the amount moved routinely exceeds the distance it is shifted by (the ordinary case whenever the previously-selected directory's own path was short, e.g. just the card's root directory), the two ranges overlap -- yet the copy is performed with a plain byte-copy primitive that is only well-defined for non-overlapping memory. AddressSanitizer's interceptor for that primitive detects the overlapping source and destination ranges at runtime and aborts before any data corruption can actually occur.
