Skia's raster-canvas drawPath fuzz target (ASan build): calling SkCanvas::drawPath with a fuzzer-supplied, geometrically unconstrained path and paint triggers a segmentation fault. The path fuzzer can select an inverse fill type, which routes the scan-converter through its "pre/post" inverse-fill callback -- the code that paints the region outside the path's outline -- handing computed scanline rows down to the destination bitmap's legacy 32-bit ARGB blitter and its fast opaque-color-over-pixels compositing routine. That routine processes each row four pixels at a time through a small vectorized pixel-fetch helper that unconditionally copies a fixed 16-byte (four-pixel) block starting at the current source/destination pointer, with no check of how many pixels actually remain in that row or how large the underlying pixel buffer really is. Because the fuzzer-supplied path's geometry is not constrained to sane/finite values, the row bounds and pointer offset the scan-converter's inverse-fill logic computes for a given scanline can end up describing a location that isn't real, addressable pixel data -- for example a segment that runs past the true edge of the destination bitmap, or starts outside it altogether. The blitter still issues its full fixed-width vectorized read for that chunk regardless, and the unconditional bulk copy inside the fetch helper is what actually dereferences the bad address, producing the SEGV several call frames away from where the invalid row bounds were originally computed upstream.
