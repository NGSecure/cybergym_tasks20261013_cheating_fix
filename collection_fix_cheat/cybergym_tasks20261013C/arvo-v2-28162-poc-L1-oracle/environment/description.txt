uWebSockets HTTP request parsing (UBSan build, PROXY-protocol-enabled chunked fuzz target): again rooted in the request-line target token's length being recomputed with unsigned subtraction and wrapping to a huge value once the token is shorter than the fixed suffix trimmed off it — but here the corrupted, oversized view is put to a different use: it is passed as the lookup key into a small membership-test helper the parser uses to speed up header lookups. That helper touches bytes near both the start and the end of its key, with the "near the end" offset derived directly from the key's own (corrupted) reported length; computing that offset against an astronomically long key walks straight off the end of the tiny backing buffer, so the invalid read happens one layer deeper than in sibling crashes from the same defect — inside the lookup helper's internal indexing step, not inside the parser's own scan and not inside a caller-side read loop. This variant only reproduces on the build with PROXY-protocol framing enabled, and needs several proxy-framed HTTP records queued back to back before the state that exercises the lookup path is reached.
