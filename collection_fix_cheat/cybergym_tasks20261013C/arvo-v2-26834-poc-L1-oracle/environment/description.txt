Envoy 的 HTTP/2 编解码器在处理 upstream 连接上收到的 METADATA 帧时，只要按流 ID 能查到对应的流状态就继续往下派发，并未检查该流是否已经收到对端的“流结束”标志。当一次响应已经完整收完、其请求侧的流状态对象已经被放入延迟删除队列并在同一事件循环内被真正释放之后，如果紧接着又有一个 METADATA 帧在该连接上完成接收，帧接收完成的回调仍会按旧的流 ID 找到（已经失效的）流对象并调用它去访问所属请求的响应解码器，从而对已经被释放的堆内存发起一次读取，构成 heap-use-after-free。根因是 METADATA 帧处理路径里“流对象是否还存在”的判断只看查找是否成功，缺了“该流是否已经结束/正在被销毁”这一步校验。
