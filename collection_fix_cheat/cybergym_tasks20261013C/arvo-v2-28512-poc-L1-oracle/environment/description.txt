SELinux's CIL policy compiler (secilc, MemorySanitizer build) reports a use-of-uninitialized-value warning that traces back to memory explicitly freed earlier in the same run, surfacing during the pass that resets a resolved policy's data structures before recomputing them. The crash needs a class-permission-set statement outside any `optional` block that references a named permission grouping which is itself only declared inside an `optional` block, where that block later gets disabled and torn down during resolution. The reset pass, which walks every class-permission-set in the whole policy, still visits the permission grouping through the outer statement's reference and reads fields of an object that was already deallocated.
