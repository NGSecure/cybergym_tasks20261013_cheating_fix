OpenSC's Oberthur AuthentIC smart-card driver (project opensc, UBSan build), exercised through the PKCS#15 fuzz target's bind/select-file path, keeps a cached copy of the currently-selected directory's card path and, on every subsequent file selection, first strips off the leading segments the newly requested path shares with that cached path so only the differing tail portion is actually sent to the card. When the cached path begins with the root-directory marker but the caller-supplied path does not, the same routine re-prepends the two-byte root marker to the front of the caller's path and bumps its recorded length up by two to account for the insertion, using a fixed 16-byte in-memory array to hold the path bytes both before and after this adjustment. The amount of data the insertion step actually shifts within that array is derived from the path's length before the two extra bytes are added back in, so for a caller-supplied path that is already near the array's maximum size, the arithmetic ends up producing a path whose recorded length exceeds the 16-byte array's own capacity by one element. That over-long length value is carried forward unchanged into the file object created for the newly selected file, and later -- on the branch taken when the card's file-control response is missing an expected security-attributes block -- a diagnostic routine that renders the path as a hex string for a trace log walks the array for exactly that many elements without ever checking the length against the array's fixed size, reading one element past the end of the stack-resident 16-byte buffer; this is what UndefinedBehaviorSanitizer flags.
