uWebSockets' publish/subscribe topic-tree fuzz target (ASan build): the library keeps a fixed-capacity array that records topic nodes with a pending, not-yet-delivered notification, plus a shared count of how many entries are currently populated. A missing per-insertion capacity check elsewhere in this same subsystem lets that count and the entries it indexes drift out of sync with the array's true 64-slot bound. The observed crash happens one step downstream of that corruption: when the routine that periodically flushes pending notifications to subscribers and clears each recorded topic's message state next runs, it walks the array up to the (already-corrupted) count and dereferences a garbage pointer read from past the array's real bounds, producing a segmentation fault on an unmapped/wild address rather than a clean bounds violation at the actual point of overflow.
