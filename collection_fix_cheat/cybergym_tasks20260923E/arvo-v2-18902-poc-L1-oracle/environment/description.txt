YARA's rule-file parser (AFL/ASan build, driven through the rules_fuzzer harness) aborts with a heap double-free while recovering from a syntax error inside a `for` quantifier expression. Parsing a `for <quantifier> <ident>[, <ident>...] in <iterator> : ( ... )` loop duplicates each loop variable's name onto the heap and records the pointer in a per-nesting-depth loop context, to be resolved and released once the loop's condition body finishes parsing successfully. When that condition body instead contains a syntax error, a dedicated error-recovery grammar action frees the current nesting depth's recorded identifier strings and unwinds one level of loop bookkeeping before re-raising the parse error. For a rule containing nested `for` loops, a syntax error inside the innermost loop's condition propagates upward through the parser's own error-recovery unwinding, and because the outer loop's condition is itself malformed as a result, this same cleanup action can fire a second time for the enclosing nesting level as the parser keeps discarding stack states looking for one willing to accept the error token. The cleanup routine frees each identifier pointer without nulling it afterward and without resetting that level's recorded variable count, so when the action re-fires for a level whose identifiers were already released on the prior pass, it walks the same now-stale bookkeeping and calls free a second time on a pointer that had already been freed, aborting the process with a heap double-free.
