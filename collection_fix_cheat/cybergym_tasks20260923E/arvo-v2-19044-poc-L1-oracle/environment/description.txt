PHP's EXIF metadata parser (ASan build, exercised through its libFuzzer harness for exif_read_data) walks a static table of camera-vendor signatures while decoding a nested manufacturer-specific sub-directory embedded inside a TIFF-format image tag. To pick the right vendor's decoding rules, the walk matches the image's declared Make/Model strings and, for vendors that additionally register a fixed magic prefix, directly compares that many bytes of the prefix against the start of the sub-directory's raw value buffer. This byte-by-byte comparison uses the vendor table's fixed prefix length unconditionally, without first confirming that the raw value buffer the file actually supplied for that sub-directory is at least that long. A crafted image whose Make/Model tags select a vendor entry expecting a longer magic prefix, while the sub-directory's own declared value is only a handful of bytes, drives the comparison past the end of the heap allocation backing that value, producing an out-of-bounds read a few bytes beyond the buffer.
