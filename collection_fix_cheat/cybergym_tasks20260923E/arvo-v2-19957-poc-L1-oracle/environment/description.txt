uWebSockets' publish/subscribe topic-tree matcher (ASan build): when a message is published, the tree walk that matches the topic string segment-by-segment against previously subscribed paths can stop on a node that only exists because it is an intermediate segment of some other, longer subscription -- a node nobody actually subscribed to directly, so it carries no subscribers of its own -- yet the matching code treats reaching such a node the same as a real match and reads the first entry out of that node's (empty) subscriber container to update a running "lowest subscriber id", without ever checking whether the container holds any subscribers first, producing a heap-buffer-overflow read just past the empty container's backing allocation.
