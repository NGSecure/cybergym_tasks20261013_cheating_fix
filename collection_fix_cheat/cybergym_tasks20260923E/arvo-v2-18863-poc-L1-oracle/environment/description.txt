libheif's bundled libde265 HEVC decoder (ASan build): a heap-buffer-overflow read through a wild pointer occurs in the multithreaded SAO (Sample Adaptive Offset) in-loop-filter worker while it is applying SAO to the chroma planes of a picture that was decoded as monochrome. Root cause: the worker thread only checks the current slice header's chroma-SAO-enable flag before running the filter over the Cb/Cr planes, with no check that the picture actually has chroma planes at all, so a monochrome-coded picture whose slice header still carries that flag reaches the chroma filtering path anyway; the picture's chroma-plane base pointer for that case was computed by the image allocator via plain pointer arithmetic on top of a never-allocated chroma buffer instead of being left null, so the filter ends up dereferencing an unrelated, "wild" heap address when it reads a chroma sample.
