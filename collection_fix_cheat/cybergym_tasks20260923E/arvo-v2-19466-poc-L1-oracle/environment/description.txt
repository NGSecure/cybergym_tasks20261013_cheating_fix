This is a heap out-of-bounds read in nDPI's TLS certificate-detection logic, triggered while it scans the raw bytes of a captured X.509 certificate looking for a specific three-byte marker pattern that identifies where a certificate's subject common name begins. Once such a marker is found, and after skipping over any bytes that are not printable at the start of the matched region, the code copies a fixed number of bytes — always equal to the full capacity of a local scratch buffer minus one, regardless of how many bytes of the certificate actually remain after the current position — into that scratch buffer to build a null-terminated copy of the name. Because the amount copied is never derived from how much data genuinely remains in the certificate payload beyond the marker, a crafted certificate in which the marker sits close enough to the end of the captured packet causes the fixed-size copy to read past the end of the heap buffer backing the payload.
