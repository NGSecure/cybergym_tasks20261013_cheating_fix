PHP's mbstring extension, when compiling a user-supplied regular expression through its bundled Oniguruma regex engine, runs a post-parse optimization pass that computes how many characters wide each look-behind assertion's body will always match, so that width can later be treated as a fixed value rather than re-derived at match time. Inside that computation, a quantified sub-expression that repeats its body an exact, fixed number of times is handled by first working out the body's own length classification into a scratch variable, and only copying that classification (and the resulting multiplied length) into the value the caller will see once the body's own classification turns out to be a single fixed length. If the quantified body's classification is instead something other than a single fixed length -- for example because the body is itself a top-level alternation of branches whose lengths differ from one another -- the computation still reports success without ever recording any classification for the caller at all, leaving that output variable holding whatever unrelated stack contents happened to occupy the slot. The look-behind-width logic that runs immediately afterward unconditionally branches on that classification to decide whether the assertion has a usable fixed width, so it ends up reading and acting on a value that was never actually written. MemorySanitizer flags the read the moment a pattern is compiled where a fixed-count-repeated quantifier's body is itself a top-level alternation of differently sized branches, nested inside a look-behind assertion.
