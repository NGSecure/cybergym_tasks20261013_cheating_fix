binutils' BFD library (ASan build): parsing an HP-UX SOM archive's library symbol table computes the byte size of an internal hash-chain-offset table by multiplying an unvalidated 32-bit count taken straight from the archive header by a small per-entry width, using the same fixed-width integer arithmetic as that count. A large enough attacker-controlled count overflows this multiplication and wraps to a much smaller byte size, so only a tiny buffer gets allocated, while the code that walks the hash chains afterward still iterates the full, un-wrapped original count and reads one big-endian 32-bit offset per iteration -- running past the end of the undersized heap buffer and producing a heap-buffer-overflow read.
