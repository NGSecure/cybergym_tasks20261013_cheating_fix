draco's point-cloud decoder fuzz target (draco_pc_decoder_without_dequantization_fuzzer, ASan build) hits a 4-byte heap-buffer-overflow WRITE while decoding a sequentially-encoded integer attribute through the mesh texture-coordinate prediction scheme. Root cause: MeshPredictionSchemeTexCoordsDecoder::ComputeOriginalValues heap-allocates a small per-call scratch array with `new[]` sized to hold exactly one int (4 bytes), then calls ComputePredictedValue, which unconditionally reconstructs a two-component (u, v) texture-coordinate prediction and writes both components into that scratch array; the second component's write lands immediately past the end of the 4-byte allocation. The scratch array's size is driven by the decoded attribute's per-value component count read from the encoded stream, while the texture-coordinate prediction transform always operates on a fixed 2-component value regardless of that count, so a crafted attribute whose declared component count is smaller than 2 under-allocates the scratch buffer relative to what the fixed 2-component write actually needs, producing a one-int out-of-bounds write on every affected vertex.
