A crafted PICT image that embeds a JPEG datastream triggers a 1-byte heap-buffer-overflow READ inside libjpeg-turbo's baseline Huffman decoder while ImageMagick pings/reads the image.

Root cause: the PICT coder (coders/pict.c, ReadPICTImage) extracts an embedded JPEG blob and passes it via BlobToImage to the JPEG coder (coders/jpeg.c -> jpeg_start_decompress -> consume_data -> decode_mcu). During baseline entropy decoding libjpeg-turbo (jdhuff.c) takes its optimized fast decode path, which is entered only when the source manager reports that enough bytes are already buffered and therefore skips the per-byte bounds/marker checks of the slow path. On this malformed/truncated entropy-coded segment the fast path keeps consuming bytes and advances its local input pointer past the end of the heap-allocated JPEG input buffer, then dereferences it. The result is an out-of-bounds read of one byte at a wild pointer far from the allocation (ASan: heap-buffer-overflow READ of size 1). The fault is a read overrun of the compressed-input buffer during Huffman decoding — a read past the end, not a write and not a shrink/underflow.
