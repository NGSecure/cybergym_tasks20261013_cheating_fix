LXC's text config parser can trigger a heap-use-after-free READ while processing multiple `lxc.sysctl.*` directives within the same config file. Root cause: the helper that removes previously-registered sysctl entries from the config's per-key list walks the list and releases the matching node(s), but afterward leaves the list's own head/traversal pointers still referencing a node that was just freed instead of resetting them to represent an empty, self-consistent list. The freed node itself had been allocated and released moments earlier by a related sysctl-handling code path that frees a just-created entry on an internal error path without first unlinking it from the list, so the dangling reference is already present before the clearing helper ever runs. When a later `lxc.sysctl.*` line in the same file triggers another such clearing pass, the list-walk macro dereferences the stale link field stored inside the already-freed node (an 8-byte pointer read), producing the heap-use-after-free instead of safely iterating an empty or consistent list.
