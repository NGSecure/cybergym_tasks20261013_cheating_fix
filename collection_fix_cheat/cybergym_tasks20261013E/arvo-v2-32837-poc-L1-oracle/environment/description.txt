skcms (ICC color-profile parser, fuzz_iccprofile_atf fuzz harness, ASan): when parsing a PCS-to-device ("B2A") transform tag encoded as the one-byte-precision multi-function lookup-table variant, the same shared table-header decoder used for the sibling A2B direction takes a single untrusted byte straight out of the tag giving the input-channel count, stores it on the output B2A transform struct, and immediately loops that many times writing a per-axis grid-resolution byte into a fixed 4-element array on that struct. For this direction the only channel-count validation the decoder performs is an exact-match check (the count must equal 3, the fixed number of PCS input channels a B2A table is defined to have), and — same as in the A2B sibling code — that check is placed after the fill loop rather than before it, with no separate "not larger than the array" guard ahead of the loop either. A crafted profile can therefore set the input-channel byte to a large value, driving the fill loop through far more iterations than the 4-slot array can hold; the resulting run of one-byte writes continues past the array and into the adjacent stack memory of the calling frame, corrupting stack contents until it collides with a guard region — reported as a stack buffer overflow write.
