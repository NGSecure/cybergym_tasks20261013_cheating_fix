wolfSSH server-side fuzz target running against its bundled wolfCrypt backend (MemorySanitizer build): during session teardown the server sends a channel-EOF SSH packet, and the harness's own byte-level output-integrity check (which re-reads every byte the library hands to the network layer before it goes out) flags that the packet's payload buffer still carries some bytes that were never written. Those unwritten bytes trace back to an earlier allocation: the buffer wolfCrypt's malloc wrapper handed back when the server grew and prepared its own outgoing key-exchange-init packet during a highwater-triggered re-key. That allocation's tail was sized ahead of the content actually written into it, and the buffer's own bookkeeping of how much of it holds real data is not put back into a clean state once the key-exchange send moves on, so the same buffer's leftover, never-overwritten tail is still what gets reused — and shipped out on the wire — when the connection later builds and sends the unrelated channel-EOF packet.
