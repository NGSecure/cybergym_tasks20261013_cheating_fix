libtiff's RGBA image reader (tiff_read_rgba_fuzzer target, ASan, 32-bit build), when it encounters a TIFF whose strip/tile data is compressed with the legacy "old-style" JPEG (OJPEG) scheme, hands the entropy-coded scanline data off to the bundled libjpeg (turbo) JPEG decompressor to produce the pixel data. Inside that decompressor's baseline (non-progressive) entropy decoder, the optimized "fast path" MCU-decoding routine resolves each decoded Huffman code into an actual coefficient value by adding a per-table offset to the raw code and using the sum directly as an index into a fixed 256-entry symbol/value lookup table -- without first reducing that index back into the valid 0-255 range. For most well-formed Huffman tables the arithmetic keeps the index in range, but a crafted/degenerate Huffman table (reachable via a crafted OJPEG-compressed strip) can drive the unmasked index far outside the table's bounds. The resulting 1-byte read lands well past the table's heap allocation (ASan reports it as hitting a "wild pointer", i.e. nowhere near the buffer's redzones), during the low-level Huffman symbol lookup that happens on essentially every decoded coefficient in that fast decode path. The corrupted-but-in-range-looking value produced by this read then continues to be used downstream as if it were legitimate coefficient data.
