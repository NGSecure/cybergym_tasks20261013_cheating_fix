OpenSC's synthetic PKCS#15 emulation for Oberthur smart cards can drive an AddressSanitizer-detected heap-buffer-overflow read of a couple hundred bytes past the end of a small heap allocation while decoding a certificate's stored metadata.

Root cause: the emulation layer reads a raw metadata blob for a certificate object off the (simulated) card into a heap buffer that is calloc'd to exactly the number of bytes actually returned by that read — often just a few dozen bytes. It then walks the blob as a sequence of tag/length/value fields: a fixed 2-byte tag, then for the label field a 2-byte big-endian length prefix taken straight from the blob, followed by that many bytes of label data. The length is clamped against the destination struct field's own fixed capacity before the copy (so the copy can't overflow the destination), but nothing clamps it against how many bytes are actually left in the source blob. Because the length prefix is untrusted data pulled from the blob itself, a blob whose declared label length is much larger than the handful of bytes that truly follow it lets the subsequent copy read straight past the end of the small heap allocation while staying safely within the destination — a classic length-prefixed-field trust bug where the bounds check protects the write side but not the read side. The sibling ID field parsed right after the label has the identical missing check, as does the equivalent private-key-parsing routine elsewhere in the same file.

The upstream fix is scoped exactly to this parsing code: it adds an explicit "does the declared field length still fit inside what was actually read" check before every one of these length-prefixed copies (label, ID, and the analogous fields in the private-key parser), rejecting the record with an error instead of trusting the in-blob length outright, and also plugs a buffer leak on those now-added early-exit paths. That is a precise match for the observed crash: the crashing read is the exact memcpy this check now guards, on the exact code path (parsing a certificate's stored metadata during synthetic-PKCS#15 initialization) shown in the crash trace.
