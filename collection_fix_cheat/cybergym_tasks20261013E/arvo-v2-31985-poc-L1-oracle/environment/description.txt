LibRaw (MSan build, libraw_cr2_fuzzer): while LibRaw decodes a crafted Kodak-format raw image that uses the vendor's proprietary "65000-series" block-compressed sample encoding, a use-of-uninitialized-value warning fires much later, during the black-level-normalization step that runs near the end of raw processing (after unpacking and the raw-to-image conversion, just before demosaic/color work begins). The 65000-series block decoder works by decoding runs of coefficients into a small fixed-size local (stack) buffer that holds one decoded block's worth of samples, which the caller then copies out wholesale into the row of raw pixel data it is assembling. Root cause: for certain malformed or truncated encodings, the decoder's inner loop can stop consuming input -- for example because it runs out of coded bits or reaches a decode state it treats as terminal -- before every slot of that per-block buffer has actually been written, but the caller has no way to detect this and unconditionally copies the entire buffer, including the never-written tail, into the pixel row. That partially-initialized data then survives a second, unrelated bulk copy that builds the library's public per-plane image array out of the raw pixel buffer. When the black-level-subtraction step later walks every sample of every color plane in that image array to remove the sensor's per-channel black offset, it reads those still-uninitialized trailing samples as if they were genuine pixel values -- the sanitizer is flagging a read of stale stack memory that survived two by-value copies downstream, not an out-of-bounds access, an integer overflow, or a null/dangling-pointer dereference.
