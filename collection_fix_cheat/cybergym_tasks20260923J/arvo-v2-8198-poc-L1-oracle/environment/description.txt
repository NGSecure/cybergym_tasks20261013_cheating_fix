A bug in GDAL (UBSan bad-cast on an invalid vtable pointer) occurs while serializing a vector layer to the XLSX (Excel) output format: for each populated cell the code converts the field's column index into its spreadsheet-style letter label (A, B, ... Z, AA, ...) into a small fixed-size stack buffer sized only for a few letters, with no check that the encoding actually fits; a layer with enough fields drives the index past what the buffer can hold, so the encoder overruns it and clobbers adjacent stack memory - including the local variable holding the still-open output file handle for the current worksheet. The very next write call then dereferences that corrupted handle as if it still pointed to a live file object, and since the memory it now points to is unrelated leftover data rather than a valid handle, the virtual dispatch fails.
