Feeding a crafted IPv6 packet into Open vSwitch's flow-key extraction path causes a 1-byte heap-buffer-overflow read while decoding the ICMPv6 payload that follows the IPv6 header.

Root cause: the IPv6 header sanity check compares the header's declared payload-length field against the *total* number of bytes remaining in the packet buffer, instead of against the bytes remaining once the fixed-size IPv6 header itself has been consumed. This lets a payload length that overstates the true remaining payload by up to one header's worth of bytes pass validation. The extractor then trusts this inflated remaining-length value when it walks past the IPv6 header into the upper-layer protocol data, reading one byte beyond the end of the actual packet buffer.
