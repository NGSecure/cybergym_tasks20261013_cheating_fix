ImageMagick (MSan build), MVG (Magick Vector Graphics) decoder: rendering a stroked polygon primitive that carries a dash pattern (stroke-dasharray) allocates a scratch vertex buffer sized for the worst-case number of dash/gap segments the pattern could produce, via a plain heap allocation that does not zero-fill memory. The routine that walks the polygon's path and splits it into individual dash and gap segments only writes as many buffer entries as the actual dash pattern happens to generate for that specific polygon, leaving the unused tail of the (over-sized) buffer untouched. That buffer is then copied wholesale and consumed in full a few calls later, when the dash segments are traced into the final stroked outline, so MemorySanitizer reports a use of uninitialized memory when the untouched tail entries are read. Root cause: the dash-segment scratch buffer is never cleared (or its actually-used length never tracked/enforced) before downstream code reads across its whole allocated extent instead of only the portion the dash generator actually populated.
