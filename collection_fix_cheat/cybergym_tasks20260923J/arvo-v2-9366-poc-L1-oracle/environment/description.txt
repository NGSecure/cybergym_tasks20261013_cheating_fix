This is a heap-buffer-overflow READ of 8 bytes (one double) that happens while the vector-drawing engine renders a dashed stroke primitive parsed out of an MVG script. When the engine enters a nested drawing scope it duplicates the current graphic state, including the dash-pattern array; the duplication routine sizes and fills the new buffer by scanning the source array for the first near-zero "terminator" value and then allocating/copying only that many entries, up to and including the terminator itself. The stroke-dashing code that later consumes this duplicated array walks it cyclically while stepping along the path: on each dash transition it advances its index by one and immediately re-reads the entry at the new index to decide whether it has reached the terminator and must wrap the index back to the start. That look-ahead read assumes one extra slot of slack beyond the terminator position that the duplication routine never provisioned, so for certain dash-array lengths (their parity relative to how the original array was populated) the advancing index lands exactly one double past the end of the freshly allocated, undersized buffer, producing the out-of-bounds read reported by the sanitizer. The corresponding fix widens both the allocation and the number of bytes copied for the duplicated dash-pattern array by one additional element, giving the cyclic look-ahead check the headroom it was implicitly relying on.
