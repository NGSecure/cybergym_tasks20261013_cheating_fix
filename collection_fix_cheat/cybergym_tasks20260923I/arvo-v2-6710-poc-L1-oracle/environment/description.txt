open62541 OPC UA server: handling an AddNodes service request, the routine that copies a child node into the address space and wires up its parent/type references calls a helper for that reference bookkeeping; when the reference/type check inside that helper fails, the helper itself deconstructs and releases (frees) the just-copied node from the node store as cleanup. Control returns to the copy-node routine, which is not aware the node was already released on that failure path and goes on to delete/free the same node a second time as its own cleanup step — so the node's identifier fields are read off an already-freed heap allocation: a heap-use-after-free read caused by a double release of one node along an AddNodes error path.
