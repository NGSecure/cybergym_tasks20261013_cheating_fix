Decoding a crafted HEIC/HEVC image triggers a 1-byte heap-buffer-overflow write inside ImageMagick's bundled H.265 bitstream decoder while it builds the reference-picture-set state for a video slice. The underlying cause is that the decoder trusts an attacker-controlled count of short-term reference pictures parsed earlier from the coded header without fully rejecting an invalid or out-of-range value for it; a malformed stream can make this count pass the decoder's existing sanity checks even though the value itself is bogus. That uncorrected count is later used both to size a small per-slice heap buffer and to drive the loop that populates it, and the two computations disagree by one element, so the final write lands one byte past the end of the allocation. The fault is a validation gap in the header-parsing stage, not in the write routine itself: tightening the check on the reference-picture count so a clearly invalid value is rejected before it can influence any downstream buffer sizing or indexing prevents the overflow.
