Decoding a crafted HEIC/HEVC image triggers a 4-byte global-buffer-overflow read inside ImageMagick's bundled H.265 bitstream decoder, while it converts a per-transform-unit quantization value into a coefficient-scaling factor during residual/transform coefficient decoding. That step selects an entry from a small, fixed-size global lookup table using an index derived from the current quantization parameter, but the value feeding that index is not fully constrained to the table's valid range before it is used; when the derived quantization value can end up negative, computing an index from it yields a small negative offset instead of wrapping back into range. Because this lookup table sits directly adjacent to another small global table in memory, indexing a few entries before the table's own start does not immediately fault — it lands in the padding/redzone just past the neighboring table, producing an out-of-bounds read rather than an obvious crash at the table's own boundary. The root cause is upstream of the lookup itself: the quantization value used to compute the table index is not validated or clamped to a legal range during header/coefficient parsing, so a malformed bitstream can drive it negative and steer the subsequent table access out of bounds; constraining that value to its valid range before it is used as an index would prevent the underflow.
