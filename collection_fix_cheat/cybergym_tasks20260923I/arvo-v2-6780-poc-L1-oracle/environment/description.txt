ImageMagick (MSan build): decoding a WordPerfect Graphics version-2 (WPG2) bitmap stream allocates a per-scanline byte buffer from the heap without zeroing it first, and the compressed row-decoding path does not always write every byte of that buffer for a given line, leaving trailing bytes holding stale heap content. Those raw row bytes are subsequently walked to derive palette-lookup values that are passed into a shared helper which clamps/wraps a value into the valid range of the image's color table before using it as an index; when the byte feeding that clamp happens to be one of the positions the decoder never actually wrote, the clamp itself consumes uninitialized memory, which is what MemorySanitizer flags as use-of-uninitialized-value. The bug is not an out-of-range palette index reaching the lookup — it is that the value fed into the range-clamping step was itself never initialized. The fix zero-fills the whole scanline buffer right after allocation, before the decode loop starts, so any byte the compressed stream leaves untouched reads back as a defined 0 instead of leftover heap garbage.
