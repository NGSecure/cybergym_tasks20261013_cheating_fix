ImageMagick's HEIC reader delegates HEVC bitstream decoding to its bundled libde265 library (ASan build): a heap-buffer-overflow write occurs while resolving a slice's long-term reference pictures against the decoder's picture buffer. Root cause: right after entering a new slice, the decoder allocates a small per-picture "seen" bookkeeping array sized to however many pictures currently sit in its decoded-picture buffer at that instant. While it then walks the slice header's list of long-term reference pictures, any reference that cannot be found among the pictures already present is handled by synthesizing and inserting a placeholder picture to stand in for the missing one, which grows the decoded-picture buffer by one slot; the newly inserted placeholder's buffer index is then used to mark the corresponding slot in the bookkeeping array as seen. That bookkeeping array, however, is never resized after the buffer grows, so its valid index range still reflects the buffer's smaller size from before the insertion. A crafted bitstream whose slice header references long-term pictures that are absent from the decoder's buffer reliably drives this placeholder-insertion path, and the immediately following bookkeeping write then lands one element past the end of the array's heap allocation.
