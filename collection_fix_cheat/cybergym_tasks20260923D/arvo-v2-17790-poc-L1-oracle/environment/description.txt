In this userland SCTP stack, MemorySanitizer reports a use-of-uninitialized-value read inside the block-processing step of the keyed message-digest routine (HMAC over a SHA-1-family hash) that the stack uses to authenticate outgoing control traffic. The crash happens while the association is building and signing an acknowledgment chunk in response to a peer's dynamic-address-reconfiguration request: the code assembles the outgoing acknowledgment's payload by copying bytes out of the inbound message's buffer chain into a fresh, heap-backed buffer, then hands that buffer's full declared length straight to the digest computation so the acknowledgment can be authenticated before it is sent. The copy step that populates this buffer does not necessarily write every byte across its whole declared length -- for example, trailing bytes beyond what was genuinely copied from the inbound data can be left exactly as the backing allocation already held them, uninitialized. Because the digest routine consumes the buffer's declared length rather than only the portion that was actually written, it ends up mixing that indeterminate trailing content into the authentication computation together with the legitimate acknowledgment bytes, and the block-processing step is where the sanitizer catches the read of that never-written region.
