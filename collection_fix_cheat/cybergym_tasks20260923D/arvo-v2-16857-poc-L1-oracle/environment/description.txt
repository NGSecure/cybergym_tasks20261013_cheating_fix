When this library parses a MATLAB level-4 (v4) sparse-matrix variable, it allocates the sparse container, reads the row-index array in from the file, and then reads a short numeric field into a local scalar so it can derive one of the matrix's two declared dimensions from that field; the code immediately casts that scalar and range-checks it (rejecting negative or absurdly large values) before continuing. The read of that scalar into local storage never confirms that the read actually transferred a value from the file; if the input ends, or is otherwise truncated, exactly where that field should begin, the read call comes back having copied nothing, yet the surrounding logic has no way to detect this and goes ahead and consumes the scalar's leftover stack contents as if they were the real field. The resulting dimension decision and range check therefore both operate on data that was never actually written by anything, which is why the crash is a direct memory-sanitizer flag on the use of an uninitialized value at the moment that scalar is consumed, rather than any kind of out-of-bounds read or write; the underlying gap is the missing check on how much data a short scalar read actually delivered before the code trusts and acts on it.
