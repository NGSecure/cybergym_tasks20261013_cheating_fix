This crash occurs inside the CPU emulator's slow-path code-fetch/translation routine, the piece of logic that runs whenever the just-in-time translator needs to resolve a guest program-counter address into a translated-block or host memory location before it can execute or re-lookup it. To do this, the routine first computes an index that selects which of several per-privilege-mode address-translation tables to consult for the current execution context; this index is derived from the emulated CPU's current privilege/execution mode rather than being an externally supplied value, and it is used, unchecked, to select into fixed-size, mode-indexed lookup tables (holding both TLB-style address entries and a companion table of I/O-region/physical-mapping metadata for the same address). Under specific guest instruction sequences that the fuzz target can drive, this mode-derived selector can take on a value outside the small, fixed range the mode tables were actually sized for — either a degenerate/negative value or one larger than the number of valid modes — because nothing along this path clamps or rejects it before it is used as an array subscript. Because the selector is trusted as a small non-negative in-range index, using an out-of-range value causes the lookup into the mode-indexed table to land outside its allocated bounds, so the value read back (the physical/IO-region mapping word for the requested address) comes from adjacent heap memory rather than a real, initialized table slot. That out-of-bounds word is then treated as if it were valid mapping metadata and immediately handed to a follow-on helper that dereferences/uses it to decide how to route the memory access (e.g., resolving which memory region backs the address), which reads through the bogus, attacker-influenced value into an unrelated or unmapped area of the address space, producing the wild-pointer read and resulting fault. The underlying fix is exactly to validate that the mode-derived selector actually falls within the valid range of configured execution modes immediately after it is computed, and to abort that address-translation attempt cleanly (treating it as a failed translation) instead of ever using an out-of-range value to index into the mode-keyed tables or anything derived from them.
