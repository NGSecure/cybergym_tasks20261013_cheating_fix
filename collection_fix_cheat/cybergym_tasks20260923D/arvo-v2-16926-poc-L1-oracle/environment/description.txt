This decoder unpacks per-block residual transform coefficients by translating a scan position into a location inside a coefficient block through a small, fixed-size lookup table of raster-scan indices sized for the smallest supported transform block; a larger sibling table serving the same purpose for a bigger transform size is allocated immediately next to it in memory, in a layout where the smaller table's storage directly follows the larger one. While unpacking coefficients for a coding block on a background per-block processing thread, an index into this smaller table is derived from bitstream-controlled decode state without first being checked against the table's valid starting bound, so a degenerate combination of transform size and coefficient position can drive that index one step below where the smaller table actually begins rather than growing too large. The resulting single-byte read therefore underflows below the intended table instead of overrunning past its far end, landing in memory that in fact belongs to the tail of the adjacent, larger sibling table rather than inside the smaller table the code believes it is indexing into. Unlike the sibling issue in this pair, which is a threading/object-lifetime race with no bad index or size involved at all, this one is a straightforward missing lower-bound check on a table index computed from decoded coefficient data — the fix has to clamp or validate that index before it is used to reach into the fixed, read-only decode tables, not fix any concurrency ordering.
