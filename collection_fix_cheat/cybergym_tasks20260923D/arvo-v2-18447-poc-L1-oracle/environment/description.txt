The crash occurs inside the config-file tokenizer while it is scanning an ordinary bareword or unquoted string value. The scanner consumes input one byte at a time in a loop until it hits a character that can no longer be part of the token (whitespace, an equals sign, a comment marker, and so on), and once it decides the token has ended it deliberately steps its read cursor back by one position so that the terminating character is left unconsumed for whatever comes next. That "step back" operation always assumes there is a byte sitting immediately before the cursor's current position that it can safely inspect. The problem surfaces when the unquoted value runs all the way to the very last byte the parser was told made up its input, with nothing following it: the byte-consuming primitive correctly recognizes that no more input remains and stops advancing, but the subsequent unconditional step-back still walks the cursor across that boundary and reads whatever memory happens to sit one position past the end of the buffer the parser believes it owns, rather than treating the exhausted-input condition as terminal. Because the fuzz harness backs this buffer with a fixed-size global array sized to exactly the bytes actually supplied, that single stray read lands outside the array and is flagged as an out-of-bounds access.
