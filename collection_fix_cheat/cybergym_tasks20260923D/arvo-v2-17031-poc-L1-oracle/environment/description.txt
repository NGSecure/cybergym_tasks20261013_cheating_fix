This is a one-byte heap-buffer-overflow write uncovered while feeding a fuzzed Annex-B HEVC bitstream through the decoder's slice-parsing pipeline. Once a picture's sequence-level dimensions are known, the decoder allocates a per-picture map that records, for every coding-tree block, which neighboring prediction unit touches it; the map is sized exactly to that picture's width and height in coding-tree blocks. Populating this map for a given coding-tree block requires knowing that block's row/column position within the picture, which the parser normally carries forward slice by slice as it works through a picture in raster order. The bug is reachable when a slice arrives that the bitstream does not mark as the first slice of a new picture, but that is nevertheless the very first slice the decoder actually processes for that picture (because, from the decoder's point of view, no prior slice has legitimately opened this picture yet). When such a slice is additionally signalled as depending on an earlier sibling slice's header, the parser copies header state — including the coding-tree-block position it will use going forward — from whatever slice-header slot happens to be sitting in that memory location, left there by an entirely different, previously decoded picture that is not guaranteed to share the same dimensions. Slice-data parsing then trusts that inherited, stale coordinate to compute where in the freshly allocated, current-picture-sized map to write the neighbor-index entry for the coding-tree block being processed. When the inherited coordinate does not fit the current picture's smaller geometry, the computed offset runs past the end of the newly allocated map, and the single-byte store lands just beyond it. The corresponding fix closes this by refusing to treat any slice as a valid "depends on a previous slice" continuation unless a real slice has already legitimately begun the current picture, so a slice arriving in that inconsistent state is discarded instead of being parsed with borrowed, dimension-mismatched position state.
