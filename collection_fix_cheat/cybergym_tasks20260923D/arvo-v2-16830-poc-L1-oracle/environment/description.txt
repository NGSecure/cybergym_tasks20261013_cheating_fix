This is a 1-byte heap-buffer-overflow read that occurs while an interlaced image is being decoded row by row within one interlacing sub-pass. After the raw bytes of a row are read into a per-row buffer, the decoder unconditionally re-reads a single byte located immediately past that row's own data in order to cache the filter-type tag that begins the following row, so it can be reused on the next iteration without issuing a fresh read for it. Every row in a sub-pass except the very last one is read with one extra trailing byte precisely to make that peek valid, but the final row of a sub-pass is deliberately handled as one byte shorter, since there is no subsequent row within that sub-pass to look ahead into. Because the byte-caching step ran unconditionally regardless of which row was current, when the loop reached that shortened final row it still attempted to read the byte at the position that would hold a following row's filter tag — one byte beyond what was actually read and allocated for that row — producing an out-of-bounds heap read. Small or heavily interlaced inputs are especially prone to triggering this, since the sub-passes of such an interlacing scheme can become extremely narrow near the end of decoding, so the undersized final row's buffer is only a few bytes long and the one-byte overread lands squarely outside the heap allocation rather than merely in uninitialized padding. The corrected logic performs the look-ahead byte copy only for rows that are not the last one in their sub-pass, so the shortened final row is never probed past its own allocated length.
