This crash sits several layers below ImageMagick's own HEIC-loading code, inside the embedded H.265/HEVC bitstream-decoding library that ImageMagick calls out to once it recognizes a HEIF/HEIC container: after the container's compressed video-sample bytes are extracted, they are handed off, together with a length value describing how many bytes belong to that one bitstream unit, to a routine whose job is to copy those bytes into a per-unit buffer it owns. That routine first decides whether its existing buffer is big enough by comparing the incoming length against the buffer's current capacity, growing the buffer only when the requested length is larger than what is already allocated; because the length is carried as a signed value derived from attacker-controlled container metadata, a malformed input can drive it to a negative number, and a negative number always compares as smaller than any non-negative capacity, so this bigger-than-capacity check is trivially satisfied without ever bypassing it in the way it was meant to guard against -- the routine concludes no growth is needed and skips allocating real memory. The same still-negative length is then fed straight into a raw block copy whose size parameter is an unsigned type, so the negative value is reinterpreted not as "no bytes" or "an error" but as an enormous positive byte count; the copy therefore proceeds to move what looks like billions of bytes from the caller's source pointer into the small, unenlarged destination buffer. Because the source pointer at that point does not actually reference a real, fully-sized source region, and because the implied copy length is so large it wraps the address arithmetic used to sanity-check memory ranges, the read and write ends of the copy are flagged as impossibly overlapping and the process aborts. The underlying defect is that a per-unit length that should only ever be a small, non-negative count is validated solely against "is it larger than what I already have," which silently admits negative values as if they were harmlessly small, when what was actually needed was an explicit rejection of any degenerate or negative length before it is ever used to size or drive a copy.
