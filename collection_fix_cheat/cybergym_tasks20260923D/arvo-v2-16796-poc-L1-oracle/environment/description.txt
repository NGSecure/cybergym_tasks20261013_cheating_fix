This is a heap-use-after-free read that occurs while the library is stepping through the frames of a multi-frame GIF image, at the point where it decides whether the current frame's palette contains any non-greyscale colours. To make that decision, the code resolves a pointer to whichever colour table applies to the frame in hand -- a per-frame local table if one is present, otherwise the file-wide table -- and it does so before the lower-level frame-descriptor parser for that frame has actually run. That parser, however, can as a side effect release the memory backing a colour table left over from handling the previous frame, since the underlying GIF-decoding layer reuses and frees per-frame colour-table allocations as it advances from one frame's header to the next. Because the pointer is captured up front rather than after the descriptor has been parsed, on some frame sequences it keeps referring to a local colour table that the parser has, in the interim, already freed and possibly reused; the subsequent read through that stale pointer to inspect the palette's entries then touches freed heap memory instead of the frame's real, currently valid table, tripping the allocator's use-after-free instrumentation. The corrected behaviour is to defer resolving which colour table applies until immediately after that frame's descriptor has been successfully parsed, so the pointer always reflects the table that is actually current at the moment it gets dereferenced rather than one snapshotted before the parse step had a chance to invalidate it.
