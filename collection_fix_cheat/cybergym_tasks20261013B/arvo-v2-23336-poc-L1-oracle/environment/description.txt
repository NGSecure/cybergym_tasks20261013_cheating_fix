RDKit molfile parsing (MSan build): once an entire V2000/V3000 CTAB has been parsed, a molecule-wide hydrogen-removal pass walks each substance group and asks, for a given atom, whether that atom is one of the group's members - a check implemented as a linear scan of the group's own atom-index list. That scan reads a list element MemorySanitizer never sees written by a real value. Following the sanitizer's own value-origin trace, the poisoned element traces back to the exact same defect class: the group's atom-bookmark-resolution helper looks up whichever atom is currently registered under a given molfile-internal bookmark number and records that atom's index into its list, but the atom object it resolves to had already been freed and swapped out for a replacement earlier in the same file - while handling an unrelated ring-bond-count / query-atom substitution directive - without the bookmark record for the discarded atom ever being cleared. The resolver hands back a pointer into freed memory, the index value copied from it is garbage, and because this particular substance group is later duplicated wholesale into the finished molecule's internal storage (a plain copy that carries the corrupted entry along unchanged), the bad value only gets read once the post-parse hydrogen-removal logic performs its membership check, well after the original parsing step that created it.
