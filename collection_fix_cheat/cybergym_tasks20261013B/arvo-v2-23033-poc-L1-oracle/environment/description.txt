LibRaw (MSan build): processing a crafted raw-camera file causes the generic per-file raw-decode buffer to be only partially populated, and the routine that copies that buffer into LibRaw's internal Bayer-pattern image array reads past the populated region into never-written heap memory, triggering a use-of-uninitialized-value warning. Root cause: the file's format signature routes it to a decoder whose unpack loop advances through the source data using a step or count derived from a crafted/inconsistent field, so it writes fewer bytes into the destination buffer than the buffer's declared dimensions call for; a later stage that walks the buffer strictly by those declared dimensions (rather than by how much data the decoder actually wrote) reads the unwritten tail as if it were valid pixel data.
