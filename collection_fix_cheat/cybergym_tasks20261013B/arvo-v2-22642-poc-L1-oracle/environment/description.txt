GDAL's gdal_translate fuzz target (ASan build): a heap-buffer-overflow write of a single 32-bit value occurs inside the raster-overview "mode" (majority-value) resampling routine, reached while GDAL computes the min/max statistics of a VRT-sourced raster band during an ILWIS CreateCopy operation, which pulls resampled overview data through the raster band's block-based RasterIO path one destination window at a time. Root cause: the routine allocates its output scanline buffer sized to the actual destination window it was asked to fill (the window's width times its height, one float per pixel), but then computes the starting offset of each destination scanline by multiplying the scanline index by the full width of the target overview band instead of by the width of the window it actually allocated for. When a caller requests a destination window narrower than the overview band's full width, the per-line stride used to index into the buffer overshoots the buffer's true row size, so scanlines beyond the first one land outside the allocation, and the majority-value pixel write for one of those later, out-of-range scanlines lands past the end of the heap buffer.
