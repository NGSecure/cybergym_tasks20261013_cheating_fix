A picture-deserialization fuzz target (AddressSanitizer build) reports a heap-buffer-overflow read flagged from inside libc's strlen. It is triggered while decoding a serialized graphics-picture record that embeds a mesh object carrying a named, optional per-attribute marker string: the decoder copies a length-prefixed, attacker-controlled byte blob out of the untrusted stream into a small fresh heap buffer, then re-interprets a field inside that copied blob as a plain NUL-terminated C string and immediately computes its length. Because nothing verifies that a terminating NUL byte actually exists within the bytes that were copied, the length computation walks past the end of the small heap allocation whenever the crafted input omits one, producing a multi-byte out-of-bounds read right at the buffer's boundary.
