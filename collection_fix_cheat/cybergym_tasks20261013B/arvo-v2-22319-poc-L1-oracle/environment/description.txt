OpenSC's PKCS#15 card-reader fuzz target (UBSan build): while binding a synthetic PKCS#15 profile for a GemSafe smart card, an out-of-bounds array write occurs on a fixed-size, stack-allocated array of per-key record structures. Root cause: the routine scans a fixed range of candidate key-directory file identifiers and, for each one that yields a plausible key record (correct record length, expected header byte, and a recognized modulus-length code), stores the parsed key data into the next free slot of that array before advancing an accepted-key counter used as the array index; the number of candidate identifiers scanned is one more than the number of slots the array actually reserves, so if every candidate identifier in the scanned range turns out to look like a valid key record, the counter reaches a value equal to the array's slot count on the last accepted record, and the write for that record lands one element past the end of the array, corrupting adjacent stack memory.
