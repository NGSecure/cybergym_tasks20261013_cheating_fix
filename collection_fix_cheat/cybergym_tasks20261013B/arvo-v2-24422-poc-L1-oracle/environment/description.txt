RDKit's SMILES-to-molecule fuzz target (ASan build): parsing the CXSMILES extension block appended after a SMILES string (the pipe-delimited "|...|" suffix used to carry auxiliary annotations such as link-node repeat counts) triggers a one-byte stack-buffer-overflow read past the end of the extension substring. The routine that consumes one such annotation reads a decimal-digit run into an integer, then unconditionally steps the cursor forward past the character it assumes is the field's separator, without first checking whether the digit run had already reached the very end of the substring. When a malformed annotation omits the expected separator and its digits run all the way to the substring's boundary, that unconditional step pushes the cursor one position beyond the buffer, and the shared digit-scanning helper invoked immediately afterward to parse the next integer field dereferences that out-of-bounds position while testing it against '0'-'9', overrunning the small, stack-allocated CXSMILES substring by exactly one byte.
