A crafted EPS/EPT file whose embedded raster preview is a 16-bit grayscale TIFF triggers a 1-byte heap-buffer-overflow READ while ImageMagick unpacks that preview's pixel data during import.

Root cause: when the TIFF preview is decoded strip-by-strip, the per-strip scratch buffer is sized as the TIFF library's own reported strip byte-count plus a small, fixed (constant-size, not image-width-scaled) safety pad. The pixel-unpacking loop that follows, however, walks that buffer one scanline at a time using a stride derived from the image's own column count and sample depth rather than from the TIFF library's per-row byte accounting, so the two views of "how many bytes make up one row" can disagree by a byte or two. For the last row serviced from a given strip buffer, this mismatch lets the 16-bit (2-byte) grayscale-sample reader step one byte past the very end of the allocated region while reading the high byte of the final sample in that row - a one-byte overread rather than an off-by-a-whole-row error, which is why it surfaces as a tiny 1-byte heap-buffer-overflow instead of a larger corruption.
