A wild-address read crashes immer's C++ persistent-vector fuzz target (ASan build) while the right end of a vector is being trimmed off (a "take"-style truncation) inside its relaxed radix-balanced tree (RRB-tree). The vector under test had been assembled by repeatedly concatenating pseudo-random sub-vectors earlier in the same run, and the harness's bound on how large a concatenation result was allowed to become was based on an approximation of the size type's numeric range rather than the smaller capacity that the tree's actual branching and leaf-width parameters can structurally support once enough concatenations add extra levels to the tree. Truncating from the right walks the tree from the root downward, and before descending into each child the walk must first read that child in order to tell whether it is itself an irregularly-shaped ("relaxed") node or a plain, evenly-shaped one, since the two need different slicing logic. Because the tree had already grown past the depth its structure can properly address, one of the child pointers stored in an ancestor node is no longer a valid node address. The very first access to that child — reading it merely to determine its shape before any size bookkeeping is even consulted — dereferences that invalid pointer and crashes, one step earlier in the tree walk than a lookup that instead reads past the end of a node's own size table.
