Binutils readelf (ASan build): while computing the dynamic symbol count from a crafted ELF's GNU-style hash section, the code also consults a MIPS-only translation table that maps GNU-hash chain slots to alternate symbol indices (only present when a MIPS extended-hash dynamic tag is set). For each hash bucket it walks a chain of slot indices computed directly from attacker-controlled bucket/chain values taken from the file, and on the very first slot of that chain it indexes into the translation table before any range check on that index has run; the chain-walking loop's own upper-bound check only takes effect starting from the second slot onward and never covers this first lookup. Root cause: a crafted bucket value can make the very first slot index land far outside the translation table's allocated size, so the unguarded lookup performs a wild out-of-bounds read and crashes the process.
