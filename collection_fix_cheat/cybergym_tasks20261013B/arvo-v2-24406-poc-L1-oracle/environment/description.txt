RDKit's V2000 molfile-to-mol streaming fuzz target (afl, ASan build): a heap-use-after-free read occurs while parsing the optional property-line block of a V2000 CTAB. Root cause: if that same property block first contains a Marvin-style SMARTS property line that swaps in a brand-new Atom object at an existing atom position, the molecule's in-place atom-replacement helper deletes the original Atom instance but does not update any atom bookmark that was still pointing at that same instance -- the bookmark table keeps holding the now-dangling raw pointer to freed memory. If a later property line in the same block records a Substance Group and adds one of its parent atoms by referencing that same stale bookmark, the code resolves the bookmark back to the freed Atom object and reads its stored index off that dangling pointer, producing the use-after-free. So the crash requires two property lines to fire in the right relative order within one CTAB block: first one that replaces an atom carrying a live bookmark, then one that consumes that bookmark afterward, by which point the object it names has already been destroyed.
