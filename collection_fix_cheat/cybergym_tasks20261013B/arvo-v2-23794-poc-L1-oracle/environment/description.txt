c-blosc's compression fuzz target (ASan build) drives the top-level block-compression API over an attacker-controlled byte buffer, using the library's own built-in LZ77-style block codec (as opposed to the third-party codecs c-blosc can also wrap). While scanning the input for repeated byte sequences, that codec alternates between two output-writing paths: copying a non-matching byte as a literal, which is checked against the caller-supplied output buffer's end before every byte is written, and encoding a detected match, which is not checked at all -- several match-encoding bytes are written unconditionally, immediately followed by one more placeholder byte the codec appends in anticipation of a fresh literal run starting right after. When an input keeps steering the codec down the match-encoding path long enough that these unconditionally-written match bytes fill the destination buffer up to its exact end, that trailing placeholder byte is still written unconditionally and lands one byte past the buffer: a 1-byte heap-buffer-overflow WRITE.
