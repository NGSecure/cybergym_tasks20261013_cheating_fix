Skia's SkVertices deserialization path (reached while decoding a serialized SkPicture image filter) rebuilds a vertex set whose per-attribute "marker name" strings are packed contiguously into one heap buffer. The buffer's size is computed by summing the length of each marker-name string, but that sum forgets to reserve the extra byte each string needs for its terminating NUL, so the allocation ends up too small by roughly one byte per named attribute. When the names are then copied into that buffer one after another with a NUL-terminating string copy, the copy for one of the later (or the only) marker name writes past the end of the undersized allocation, producing a heap-buffer-overflow write. A crafted input only needs to carry a vertices blob with at least one non-empty attribute marker name to hit this path.
