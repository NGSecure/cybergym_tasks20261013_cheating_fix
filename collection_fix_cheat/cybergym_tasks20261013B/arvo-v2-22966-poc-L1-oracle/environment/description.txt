PcapPlusPlus DNS parsing (ASan build): the label-decoding routine used when a resource record's domain name is decoded keeps a running count of how many bytes it has written into a fixed 256-byte output buffer, and before appending each plain label it only rejects the append if the count *after* appending would go past the buffer's last valid slot -- a label that lands exactly on that boundary is still accepted, leaving the write cursor sitting one slot past the end of the buffer. Root cause: if the segment immediately following that boundary-landing label is a name-compression pointer, the routine follows it through a nested call and then unconditionally writes a terminating zero byte at the current write-cursor position, with no check that the cursor is still inside the buffer -- so when the cursor is already one past the end, that unconditional terminator write becomes a one-byte out-of-bounds stack write.
