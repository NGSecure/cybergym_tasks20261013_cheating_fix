nDPI's TLS Certificate-message parser (MSan build) reports a use-of-uninitialized-value warning while walking the subjectAltName extension bytes of a certificate entry to pull out dNSName strings for hostname matching: the code advances a byte cursor across a run of ASN.1 tag/length fields (skipping over a BIT STRING length, then a fixed two-byte jump past a SEQUENCE tag, then a SEQUENCE length) purely by adding fixed or field-derived offsets, and dereferences the payload at the new cursor position for each successive skip without first checking the cursor against the payload's actual length. Root cause: the certificate payload it walks is a heap buffer that was allocated to hold the reassembled TLS record but is only partially filled with genuine packet bytes beyond the declared payload length; a certificate entry whose ASN.1 length bytes are crafted (or truncated) so the cursor walks past the real data boundary during one of those unchecked offset advances lands the next dereference on trailing bytes of that buffer that were never written by the reassembly code, i.e. still-uninitialized heap memory, rather than being stopped as an out-of-bounds read.
