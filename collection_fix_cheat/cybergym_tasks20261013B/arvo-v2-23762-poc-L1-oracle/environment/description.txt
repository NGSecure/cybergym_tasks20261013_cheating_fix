jbig2dec (MSan build, libFuzzer harness) hits a use-of-uninitialized-value read inside the low-level arithmetic-decoding primitive shared by every JBIG2 region type, while decoding a generic refinement-region segment whose typical-prediction (TPGRON) flag is set. A refinement region's decoded output is a freshly heap-allocated bitmap that the per-pixel decode loop fills in scanline order, but JBIG2 bitmaps are packed 8 pixels to a byte, so whenever a region's width is not an exact multiple of 8 the last few bit positions in each row's final byte fall outside the declared pixel width and are never touched by that loop -- they retain whatever bytes the heap allocation happened to contain at the time. Once the region finishes decoding, it gets merged into the accumulated page bitmap through an AND-style composition routine that, for speed, operates a whole byte at a time rather than bit by bit; that byte-level merge copies each row's trailing, never-written bits right along with the real pixel bits, so those never-initialized bytes are now baked into the page's own pixel data. When a later part of the same bitstream reuses that page data (as the reference bitmap for a further refinement-region decode within the same input), one of those still-uninitialized bytes ends up flowing into the arithmetic decoder's internal state as it works through the new segment, and it is there -- deep inside the generic arithmetic-decode routine, several calls away from the refinement-region code that actually produced the tainted byte -- that MemorySanitizer catches the read.
