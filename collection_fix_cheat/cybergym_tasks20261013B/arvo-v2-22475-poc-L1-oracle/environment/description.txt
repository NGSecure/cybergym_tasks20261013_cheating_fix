MemorySanitizer reports a use-of-uninitialized-value when nDPI's TLS Client Hello dissector builds an independent heap copy of a string assembled from the ALPN (Application-Layer Protocol Negotiation) extension of a Client Hello record that was reassembled across multiple TCP segments in a per-flow buffer. While copying the extension's payload into a fixed-size local buffer, the dissector bounds the copy only against the extension's own self-declared length fields (attacker-controlled), not against how many bytes of the per-flow reassembly buffer are actually backed by data the flow has genuinely received; since that reassembly buffer is grown with a plain, non-zeroing heap allocator and the code did not yet enforce strict in-order delivery of TCP segments into it, an ALPN extension that claims more bytes than have actually arrived causes never-written heap padding beyond the real payload to be copied into the local string. The subsequent length-computing scan over that string then walks into those copied-in uninitialized bytes before it ever finds a genuine terminator, which is exactly what MemorySanitizer flags.
