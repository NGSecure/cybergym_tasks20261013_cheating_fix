A smart-card driver in OpenSC that builds a padded signature APDU for a particular card family formats the caller-supplied digest into a fixed-size stack buffer by computing an insertion offset as (fixed key-length constant) minus (caller-supplied digest length), where the key-length constant is one of two hard-coded values chosen from the detected card generation. Root cause: before that subtraction the code never checks that the supplied digest length actually fits within the key length. When a signing request supplies a digest longer than the key length, the subtraction of two length values (whose common arithmetic type is unsigned) underflows to an enormous value; that huge value is then used both as an index to write a single byte into the fixed-size buffer and as the destination offset for a raw memcpy of the digest into the same buffer, producing a wildly out-of-bounds stack write driven entirely by an unvalidated, attacker/caller-controlled input length.
